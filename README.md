# PersonalFinance

Консольное приложение на Java для учёта личных финансов. Позволяет регистрировать пользователей, учитывать доходы и расходы, управлять категориями и бюджетами, а также просматривать финансовую статистику.

## Возможности

- Регистрация и авторизация пользователей.
- Создание отдельного финансового кошелька для каждого пользователя.
- Добавление доходов и расходов.
- Управление категориями доходов и расходов.
- Расчёт текущего баланса.
- Установка бюджетов по категориям расходов.
- Контроль превышения установленных бюджетов.
- Просмотр общей статистики доходов и расходов.
- Анализ расходов по категориям.
- Сохранение и загрузка данных пользователей в JSON-файл.

## Технологии

- **Java 21**
- **Maven** — управление проектом и зависимостями.
- **Jackson Databind** — сериализация и десериализация JSON.
- **Jackson JSR-310** — работа с датами `LocalDate`.
- **Java Collections Framework** — работа со списками и коллекциями.
- **BigDecimal** — точные вычисления денежных значений.

## Архитектура проекта

Проект построен с использованием принципов объектно-ориентированного программирования.

Основные классы:

| Класс | Назначение |
|---|---|
| `Main` | Главный класс приложения, консольное меню, регистрация и авторизация |
| `User` | Пользователь системы, содержит логин, пароль и финансовый кошелёк |
| `UserStorage` | Сохранение и загрузка пользователей из JSON-файла |
| `Wallet` | Управление транзакциями, категориями и бюджетами пользователя |
| `Transaction` | Абстрактный базовый класс финансовой операции |
| `Income` | Представляет доход |
| `Expense` | Представляет расход |
| `Category` | Категория финансовой операции |
| `Budget` | Бюджет с установленным лимитом по категории |
| `Statistics` | Расчёт финансовой статистики |

### Применение ООП

В проекте используются следующие принципы:

- **Инкапсуляция** — поля классов скрыты от прямого доступа, взаимодействие с объектами осуществляется через методы.
- **Наследование** — классы `Income` и `Expense` наследуются от абстрактного класса `Transaction`.
- **Полиморфизм** — работа с доходами и расходами через общий тип `Transaction`.
- **Абстракция** — общая логика финансовых операций вынесена в абстрактный класс.

## Хранение данных

Данные пользователей сохраняются в файле:

```text
data/users.json
```

Для работы с JSON используется библиотека Jackson.

При запуске приложения данные загружаются из файла. После регистрации пользователя и выхода из его личного меню изменения сохраняются.

Для корректного сохранения и восстановления данных используются:
- сериализация объектов Java в JSON;
- десериализация JSON в объекты Java;
- аннотации Jackson для определения типов транзакций;
- модуль `JavaTimeModule` для поддержки `LocalDate`.

## Установка и запуск

### Требования

- JDK 21 или выше.
- Apache Maven.

### Клонирование репозитория

```bash
git clone https://github.com/mactx13/PersonalFinance.git
```

Перейдите в директорию проекта:

```bash
cd PersonalFinance
```

### Сборка проекта

```bash
mvn clean compile
```

### Запуск приложения

```bash
mvn org.codehaus.mojo:exec-maven-plugin:3.5.0:java -Dexec.mainClass=OOP_HW.Main
```

## Пример работы приложения

Рассмотрим пример использования программы на практике. Пользователь регистрируется, создаёт категории доходов и расходов, добавляет финансовые операции, устанавливает бюджет и анализирует своё финансовое состояние.

### 1. Регистрация и авторизация

После запуска приложения отображается главное меню:

```text
Финансы.

1. Регистрация
2. Авторизация
0. Выход
```

Пользователь выбирает регистрацию и вводит логин и пароль.

После успешной регистрации данные пользователя сохраняются. Затем пользователь авторизуется и переходит в меню управления финансами.

Каждому пользователю соответствует собственный объект `Wallet`, поэтому финансовые операции разных пользователей хранятся отдельно.

### 2. Добавление категорий

Для удобства учёта пользователь создаёт категории, по которым будут распределяться финансовые операции.

Пример категорий:

| Категория | Тип |
|---|---|
| Зарплата | Доход |
| Подработка | Доход |
| Продукты | Расход |
| Транспорт | Расход |
| Развлечения | Расход |

Категория содержит название и тип (`INCOME` или `EXPENSE`). Это позволяет различать категории доходов и расходов.

### 3. Добавление доходов и расходов

Пользователь вносит финансовые операции.

Пример доходов:

| Описание | Категория | Сумма |
|---|---|---:|
| Зарплата за ноябрь | Зарплата | 100 000 |
| Выполнение проекта | Подработка | 15 000 |

Пример расходов:

| Описание | Категория | Сумма |
|---|---|---:|
| Покупка продуктов | Продукты | 12 000 |
| Проездной и такси | Транспорт | 3 000 |
| Поход в кино | Развлечения | 2 000 |

Каждая операция содержит сумму, дату, описание и категорию.

Доходы и расходы представлены отдельными классами `Income` и `Expense`, наследующими `Transaction`.

### 4. Просмотр баланса

После добавления операций пользователь может посмотреть текущий баланс.

Баланс рассчитывается как сумма всех доходов за вычетом всех расходов:

```text
Общий доход: 115 000
Общий расход: 17 000

Текущий баланс: 98 000
```

Для денежных вычислений используется `BigDecimal`, что позволяет избежать ошибок округления, характерных для типов `float` и `double`.

### 5. Установка бюджета

Пользователь может установить лимит расходов для определённой категории.

Например:

| Категория | Лимит |
|---|---:|
| Продукты | 15 000 |
| Транспорт | 5 000 |
| Развлечения | 3 000 |

При добавлении расходов программа позволяет контролировать соблюдение установленных ограничений.

Если сумма расходов по категории превышает заданный лимит, пользователь получает соответствующее уведомление.

Например, при лимите на продукты 15 000 и фактических расходах 18 000 бюджет будет превышен на 3 000.

### 6. Просмотр статистики

Пользователь может просмотреть общую статистику финансовых операций и распределение расходов по категориям.

Пример результата:

```text
Финансовая статистика

Общий доход: 115 000
Общий расход: 17 000
Баланс: 98 000

Расходы по категориям:
Продукты: 12 000
Транспорт: 3 000
Развлечения: 2 000
```

Статистика формируется на основе сохранённых транзакций. Для подсчёта расходов по категориям используется группировка операций по соответствующим категориям.

### 7. Сохранение данных

При выходе из личного меню данные пользователя сохраняются в файл `data/users.json`.

При следующем запуске приложения данные автоматически загружаются, поэтому пользователю не нужно повторно регистрироваться или вводить финансовые операции.

Таким образом, приложение обеспечивает сохранение истории финансовых операций между запусками.
